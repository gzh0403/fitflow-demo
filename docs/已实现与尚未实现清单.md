# FitFlow 已实现与尚未实现清单（P2）

本清单对应当前可交互原型，供总负责人审核。未实现项不是疏漏隐瞒，而是本阶段范围外，或明确留给后续确认。

---

## 已实现，可在原型里走通

### 视觉与结构

- 独立品牌视觉方向：清爽安静的精品工作室气质，不套用木序昭和复古
- 试用色值已用于界面，但**色值未锁定，待创始人确认**（详见视觉说明）
- 顾客端、店员端、老板端完整页面结构，不是只有首页
- 同一套页面可在桌面和手机宽度使用；店员 / 老板在宽屏下是管理后台布局，不是单纯的窄列手机框
- 按钮可点，页面可跳转，返回有效
- 角色切换有效（顾客 / 店员 / 老板），三端共用演示数据
- 店员还可切换前台 / 教练演示身份
- 操作后状态会变化，刷新后由浏览器本地存储恢复
- 一键重置演示数据
- 无权限时给出说明，而不是只把按钮藏起来

### 顾客端

- 门店首页、门店介绍、周课表、团课详情
- 团课预约（自动确认）
- 私教预约（选教练、日期、时段）
- 教练介绍
- 我的预约（待上课 / 候补 / 历史）
- 窗口内取消：退回预占次数并释放名额
- 窗口外不可自行取消，并写清规则
- 课包余次：可约、预占、已核销分开可见，并有次数流水
- 课类限制与过期课包不可约
- 出示签到码（真正核销在店员端完成）
- 上课记录
- 演示购卡（到店结算示意，不接入真实支付）

### 店员端

- 今日课次看板（待签到、满员、候补等状态）
- 课次名单：签到、批量签到、记缺席、取消
- 代顾客预约团课或私教
- 查询会员及课包余次
- 待确认私教的确认与拒绝
- 手工请假 / 补课记录（只登记，不自动改课表）
- 教练视角的我的排班

### 老板端

- 经营看板：今日约课、到课、消课、缺席、待确认、本周汇总、热门课、即将到期课包；数字由演示数据汇总
- 课程的查看、新增与编辑
- 周循环课表查看、新增周循环课、新增一次指定日期的课、单日临时停课（停课为未到店预约退次）
- 教室管理（含容量）
- 教练资料与私教可约窗口
- 会员档案、发放演示课包、全店消课与次数流水
- 营业规则：取消窗口小时数、私教自动或手动确认
- 门店资料、身份权限说明与添加演示店员
- 老板可使用店员端全部业务操作

### 已实现的业务规则

- 共用预约状态机：待确认 → 已确认 → 已到店 → 服务中 → 已完成；取消 / 拒绝 / 缺席释放名额
- 团课默认自动确认
- 私教确认方式可配置，不另起状态机；两种效果都能演示
- 先约后付：界面不出现真实收款或第三方支付对接
- 约成预占 1 次；窗口内取消退回；签到确认扣次（预占转为已核销）
- 不出现负余额，不对同一预约重复扣次
- 过期课包不可约
- 课包限制至少包含：仅团课、仅私教、仅改革器类课程
- 周循环团课课表，预约落在具体日期场次
- 教室容量按「一节课多人」计算：名额取课程上限与教室容纳的较小值；满员不可再占名额；取消后释放
- 私教一人一时段；同一教练不能同时上团课又接私教，也不能重叠两节私教；同一教室同一时段只能有一节课
- 请假补课仅手工记录，不做自动补课
- 候补已进入演示：满员后可候补，取消后按加入顺序转正（转正时才预占次数）；已在界面和本清单标明，**候补不是每家店最小可销售产品的必交项**

## 尚未实现（本阶段不做，或仅示意）

以下内容按授权范围主动不做，或只做说明，不当作已交付能力：

- 真实线上支付，以及银行卡、微信、支付宝等收款对接
- 对接美团、抖音或其他公域平台
- 门禁闸机等硬件
- 连锁、多门店、通卡
- 自动算薪、提成结算
- 自动补课（首版明确由门店手工处理）
- 复杂停卡、转卡、储值卡账户体系
- 微信订阅消息、短信等真实通知（本样品只有站内提示）
- 把转发或分享当作解锁条件（本样品没有这种设计）
- 正式微信小程序工程、云开发环境、真实部署或公开发布
- 收集或使用真实客户信息
- 并发占名额的服务端事务锁（P2 只在本地演示规则；正式环境需另行设计）
- 真实扫码枪 / 摄像头核销（现为演示签到码 + 店员点选）
- 积分商城、拼团秒杀、分销返现等营销插件

候补已可体验，但再次说明：它是演示样品中的可选项，不是每家店最小可销售产品的必交项。是否保留在后续正式范围，请总负责人或创始人确认。
